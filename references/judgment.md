# 逐项判断：能删哪些，应留哪些

检查结果要回答具体文件的去留。名称、体积和相同摘要只说明部分事实，不能代替用途判断。

| 实际情况 | 判断与依据 |
| --- | --- |
| 已废弃任务留下的临时件或失败下载残留 | 核实生成来源和任务状态，确认无需续传、恢复或排错后，提出清理具体文件 |
| 已停止使用的可重建中间产物 | 核实源文件、生成入口与参数，确认现有交付和项目引用不依赖该产物后，提出清理 |
| 完整SHA256相同，有稳定保留件，当前副本无独立用途或必要引用 | 可提出处理该副本；记录保留件并加入执行保护集 |
| 两个项目分别引用同内容文件 | 保留两个位置；删除其中一个会破坏对应项目入口 |
| 聊天附件、同步盘、办公软件缓存或恢复文件 | 保护应用管理的一侧；移动后原聊天或应用不一定能定位文件 |
| 普通目录副本只有一份应用缓存作备份 | 证据不足；先核实独立、可长期保留的完整内容 |
| 文件名叫“最终版”，但最后要求对应另一稿 | 对照用户最后要求和真实交付，逐项说明实际差异 |
| 新旧稿用途或输出规格不同 | 分别保留，例如可编辑稿与图片演示稿、高清与压缩视频 |
| 旧稿含独有批注、讲稿、实验数据、附件或恢复依据 | 保留独有内容；不能因为较旧就整目录删除 |
| 散件在保留ZIP中被完整覆盖 | 验证唯一成员、CRC、完整SHA256、原目录引用和取回方法后可提出移除散件 |
| 互为唯一保留件、保留件也将被处理 | 拒绝整个冲突组合，先指定独立保留集合 |
| 文件变化、检查不完整或依赖不明 | 保留现状，指出具体缺口；继续完成其他已查清项目 |

## 临时文件和中间产物

用生成脚本、任务日志或产物清单核实文件来源，检查任务是否结束以及文件是否仍被使用。可重建项要找到实际生成入口和保留的输入，并考虑重建成本。清理清单记录具体文件、为何已无用、保留的输入或恢复方式。目录中混有原件、有效成果或依赖时，逐项确认去留。

## 图片PPT与其他衍生容器

图片演示稿可能只是已有整页图片的包装，但不能凭“都是图片”认定无用。核对实际演示顺序、逐页图片完整摘要和顺序、讲稿备注，以及隐藏页、动画、外部链接、嵌入对象等独有内容。确认同版可编辑稿、图片、阅读版及其配套仍完整可用。只移除已核实冗余的容器，不连带删除整个历史版本。

`inspect_documents.py` 能读取页序、备注、隐藏状态、正文和媒体摘要，不验证全部动画、嵌入对象、排版或视觉等价。缺少相应检查时写明缺口，不能宣称已经完全覆盖。

## 引用和应用保护

按实际用途检查网页资源链接、项目代码、构建/复现入口、播放列表、资料导航和用户常用入口。只搜索绝对路径会漏掉相对路径、文件名和动态拼接；只搜索文本也会漏掉Office或数据库中的引用。工具搜索无命中只覆盖其声明范围，宿主仍负责必要的业务复核。

已知的微信、企业微信、WPS和代理/Git管理目录由普通执行器保护；其他软件、定制路径、已跟踪工作区、证据库和用户指定保留目录由宿主纳入保护集合。不得修改应用数据库、索引、配置、消息路径或用软链接替换附件来“维持可打开”。

## 交付具体决定

逐项记录：处理状态、路径、事实依据、保留位置、影响和执行结果。对已处理文件更新授权目录中的生成式导航，保留历史说明并补充当前入口。能删和已删分开，分类导航和实际搬移分开。原文件未动时，不用“已清理”描述建议清单。
