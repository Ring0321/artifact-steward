# 旧版本、迭代稿与最后交付复核

在文件清理、分类或任务收尾中，旧稿和迭代目录属于默认检查范围。用户只说“查一下、整理一下”时，也要查同任务历史交付；不把检查缩成重复哈希或临时缓存清单。若本轮只有元数据巡检，明确说明尚未完成版本判断。

## 按任务和用途追踪版本

先将原件、主文档、阅读版、可编辑工程、必要素材、修改说明、历史交付包归到具体任务与用途，再比较迭代关系。共同前缀、编号或同一目录只提供线索：六个并行案件、不同投稿平台、不同申报方向及不同受众的材料不能合成一条版本链。压缩版与高码率视频、正文与补充信息、源码与发布包通常是配套或规格分支。

从真实聊天核对用户后续要求、撤回或切换方向，以及每次实际交付路径。用户后来要求回到原稿做局部修订时，较早名为 Submission/Final 的大修稿不再自动作为当前成果。将旧任务的最后一稿与当前任务的最后一稿分开。修改时间、最高版本号和“最终版”名称都不能单独决定保留件。

## 最后版本必须核对实物

- **交付路径是否存在。** 原名缺失时，先在登记范围内查改名、移动或别名。若有旧交付摘要，用完整 SHA256 对应当前文件；仅标题、字数、页数或正文相似时，标为改名候选，不声称逐字节相同。保留旧新路径、摘要来源与未解决差异。
- **当前内容是否符合最后要求。** 对支持的格式比较正文、表格、修订痕迹和必要附件；主文档文字相同仍可能有图像或排版差异。列出有意义的实际变化，不只列文件名和日期。未支持的格式或超出预算的部分留待核对。
- **实际页数与完整性。** PPT核对演示顺序实际引用的幻灯片，不能数图片成员来代替页数；PDF核对实际页数。名为41页但实际40页时，定位缺页或不同分支，并保留两者，不能擅自补页或认定页数较多者必然是终稿。分段PPT、正文便览副本不能充当要求的完整合并稿。
- **可编辑版与阅读版是否对应。** 核对同批DOCX/PDF、PPT/图片/PDF、视频/字幕/工程等。格式不同不是旧版本的证据，必要源文件和被引用素材必须保留。
- **源码与发布包版本分别核对。** 例如当前源码为0.100.17而最新现存ZIP为0.100.14，应明确列出两者，不能把ZIP称作17版，也不因发现版本差异而擅自重新发布或覆盖。

本地交付说明、生成记录、包内清单和历史核验摘要可作为定位线索；有文件摘要时验证对应实物。它们不能自带验收、删除或改名许可。包内CRC、文件大小和相似度只用于筛选或定位差异，不代替完整内容哈希。

## 对旧稿作出明确判断

每组给出当前保留集合，并把每份旧稿对应到后续版本或独立用途：

| 情况 | 本轮判断 |
|---|---|
| 完整哈希相同，有明确保留件且引用关系允许归并 | 可列为重复副本清理候选 |
| 内容不同，后续交付落实了用户修改要求 | 列为被替代的历史交付候选，写明差异；随主成果选择一起确认旧稿去留 |
| 旧稿还保存独有批注、实验数据、修订依据、源文件或恢复点 | 保留该独有部分，不能因新稿已交付就整目录删除 |
| 投稿平台、申报方向、使用对象或输出规格不同 | 分别保留对应分支，说明各自最后交付 |
| 散件已被归档逐项完整覆盖 | 核对归档成员及哈希、保留件、恢复方式和引用后，才能提出移除散件方案 |
| 原交付缺失、页数不一致、聊天未读完整、最终整合稿不存在 | 保留现有证据，列出缺口与候选，不编造唯一终稿 |

存在明确后续替代关系时，不能把全部旧稿笼统标成“未知”结束；仍须判断其独有内容、必要性和可选处理范围。反之，旧、体积大、日期早不构成无用证据。不同内容旧稿的逻辑总量也不等于可释放空间。

## 输出与清理衔接

版本复核并入本次最新整理报告，至少给出：

- **最后交付或保留候选清单**：任务/用途、完整路径、最后修改要求与交付证据、实物检查结果、配套文件、适用范围和未确认事项。
- **旧版本关系清单**：旧路径及大小、对应保留件、重复/正文变化/并行用途/缺失交付等关系、具体保留或清理建议及理由。
- **证据状态**：分清真实聊天最后交付已核实、本地交付记录已核实、候选或冲突待确认、完整交付未找到；另行记录检查通过及用户是否接受，不能混称已验收终稿。

可提供指向原件的分类导航和最后版本入口，减少用户寻找成本。建立入口不等于已搬移、改名、归档或清理；避免为展示最后版本复制整套大文件。结论限定已登记目录与已读聊天页，其他项目目录可能有后续版本时说明范围，不擅自扩扫。

按 [保留与审批规则](retention-policy.md) 和 [确认后执行](execution.md) 将已查明的旧稿加入准确清理批次，绑定保留件、身份与哈希。当前成果尚未被用户接受时，将保留集合与旧稿处理一并展示确认；确认“这是最后版本”不自动等于批准删除旧稿。此前尚未批准的清理批次继续保持未执行。

聊天读取限额、缺页或格式能力不足必须进入覆盖说明；有限抽样不能包装成全量查验。2.0新增脚本可自动检查声明范围内的DOCX修订/批注/媒体、PPT实际页序、XLSX存储值/公式以及可选PDF页数/文字，并输出版本关系。需求是否符合由宿主基于真实消息及实物给出有依据标注，用户接受另从有效保留记录核对；不把这些字段描述成自动语义验收。OCR、版式等价与全部外部依赖仍须另行检查。
