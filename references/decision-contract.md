# 决定矩阵与数据合同

这些约定解释当前脚本的输出，不验证磁盘事实，也不替代用户授权。索引、建议、精确计划和实际执行记录分别保存。

## 复核顺序

先确定登记范围、物理位置和覆盖，再检查保护项与证据，最后生成建议。保留决定优先于一般候选规则。文件名、年龄和助手的“完成”声明不足以解除保护。

| 情况 | 默认结果 | 进入后续方案的条件 |
|---|---|---|
| 已登记、可重建、过观察期的过程缓存 | 可申请复核清理 | 来源与身份、保护和使用检查通过 |
| 内容一样，但分别被两个项目引用 | 保留 | 不能仅凭哈希消除任一引用路径 |
| 文件大小相同，完整哈希未做完 | 待核验 | 完整核对和明确保留件 |
| 多个不同内容的“最终版” | 待选择主成果 | 用户明确选择，所需源文件仍保留 |
| 新成果已验收但用户未选择 | 保留旧接受成果 | 用户接受新成果并指定旧版处理范围 |
| 原件、科研证据、不可重建素材 | 保护 | 用户明确修订该项保留决定 |
| 应用托管文件、项目引用或互为唯一保留件 | 保留/补查 | 不因为其他位置同内容就消除现有用途 |
| 临近执行时文件或保留件变化 | 跳过变化项 | 重新核对变化，必要时形成新方案 |
| 路径已不存在 | already_absent | 不把它计作本批实际删除 |
| 同盘移入恢复区 | 可恢复状态 | 实际空间释放记0或未知，不报文件大小为收益 |

## 建议与计划

- 判断报告的 `keep` 表示有保留理由，`needs_review` 表示证据不足，`propose_cleanup` 仅表示声明检查范围内可提出处理建议。
- `required_protected_files` 是形成执行计划时必须保护的完整保留件，不能同时列入待处理集合。
- 精确计划始终 `grants_execution=false`；导入建议或页面选择都不能自行授权执行。宿主核对真实用途、遗漏的依赖和当前用户指令。

另有 `space_record`，用来区分本批逻辑移除、恢复占用、卷观察变化和可归因的回收；同盘隔离和归档不记等量释放。并发活动无法隔离时，不给出精确可归因回收值。

可信批准不从这些文件读取。它必须由宿主记录真实用户事件，并绑定方案、内容/身份、保留件和完整影响。项目清单只能说明归属，不能授予权限。例子中的设计 ID、字节和路径均不代表真实文件已获核验。

短编号只在该报告/快照内有效，跨轮账本使用资源身份与范围作为键。稍后提醒的时间必须显式验证日历值与时区，不能只写 schema format 就假定所有校验器都已执行日期检查。

## 配置与迁移

可分发配置模板不包含本机目录。使用时根据明确范围创建个人配置，不自动开启调度或扫描其他位置。

工具自己的索引、决定账本和执行事务与应用数据库分开。缓存可以轮替，用户保留决定和未完成恢复记录必须保护。状态格式未知时保持只读，不删除旧状态以便启动。

## 验收重点

执行器拒绝保护/处理集合重叠和计划变化；宿主仍须核实用户事件的真实性。报告允许完整度不足、未知收益和负的卷观察变化，不将同盘隔离体积写成实际释放。所有真实路径、锁、状态和摘要仍按现场情况核验。
